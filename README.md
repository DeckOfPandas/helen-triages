# Helen Triages Food

About the site: https://deckofpandas.github.io/helen-triages/about/

This is a jekyll site hosted on GitHub Pages, deployed via an Action. 

This public mono-repo holds both the food and cocktails sides, with private repos holding drafts for each.

---

## Initial setup:
1. Set up Claude's GitHub access
   * Create a new GitHub user for Claude so it doesn't act as me / use my SSH keys
   * Add Claude's account as a Collaborator to the three repos
   * Logged in as Claude, create a new personal access token scoped to "repos" (classic token because fine-grained can't be generated by Collaborators)
   * Set AGENT_GH_TOKEN in .claude/settings.local.json
2. Check the three repos out locally
3. Add permissions to execute the Docker build-and-run script in the main repo directory:
    * `chmod +x .devcontainer/run.sh`
4. Run the container (running bash):
    * `.devcontainer/run.sh`
    * Builds the container if it doesn't already exist based on the Dockerfile
      * Plenty of packages are pre-installed, including Playwright and its dependencies
    * Binds the container /workspace to the primary checkout
    * Reads in AGENT_GH_TOKEN
    * Binds dotfiles for quality of life
    * Binds ports 4001 and 4002 to local ports 5999 and 6000, picked as I had to state something, and I'm unlikely to try and use those for anything else
6. Run Claude inside the container, in worktrees
7. To get terminal (bash) access to the container while running:
   * `docker exec -it helen-triages-primary bash`

Remind Claude to try the REST API rather than GraphQL as it's less likely to trigger account flagging, and remind it to space requests when making multiple (e.g. opening a batch of Issues). This is in its instructions.

Remind Claude to tag Issue numbers in commit messages because it's annoying when this doesn't happen.

## General dev workflow:
1. Pull
   * Helpful script to update drafts repos:
     * `scripts/update-drafts-repos.sh`
3. Run the Docker container:
   * `.devcontainer/run.sh`
5. Run Claude in a worktree inside the container
6. Claude will push branches and open PRs
7. Fetch the branches (local checkout)
8. View locally before merging on GitHub:
``` bundle exec jekyll serve --config _config.yml,_config_local.yml --port PORT_NUMBER```

Web artifacts turn up sometimes when importing files:
  * `find . -name '*Zone.Identifier*' -delete`

## Rebuilding the container after changes
```
docker image list
docker image rm IMAGE_NAME
```
Then build and run the container again:
  * `.devcontainer/run.sh`

## To reduce harassment by Claude, but safely

Permission for some obviously fine commands is allowed in settings. Kept deliberately narrow. 

Enforce (hooks):
  * No cd, read or write outside working directory except
    * to view other Claudes' worktrees
    * to write or redirect output to /dev/null
  * One command per bash call, so no chaining with ; or && to save a round trip
    * Chained commands are checked as a whole, so `grep ... && node ... ` harrasses me for permission even when each part on its own is allow-listed
    * A round trip is better than interrupting to harass me about things that are obviously fine 
  * Commands that build paths at run time go through committed scripts
  * Prefer exact commands for running programs because of rules ending in *, or a committed wrapper that checks its own arguments
    * There's a test for existing open-ended rules proving each wrapper refuses what it should
  * No `git reset --hard`
  * No pushing to main
  * No `pr merge` or `pr review`
