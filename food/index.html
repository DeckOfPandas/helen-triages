{% comment %} THE HEADING AND THE REVEAL LINK ARE ONE STACK -- GitHub issue #275, "centered under I KNOW WHAT I WANT". The link used to live below, inside .search--exclude with the panel it opens. Centring it under the heading from there is not something CSS can express: "centre B under A" needs A and B in one sizing context, and the heading sits inside .search-input while the link sat a level deeper in a different wrapper. Putting them in ONE grid was tried first and is instructive. The panel and the active list are in that same wrapper, so they joined the grid too, spanning every column -- and a spanning item still contributes to an intrinsic track's size, so the LEAVE OUT panel decided the width of the column the heading was meant to define. Every ingredient_groups item on this recipe, not main_ingredients. WHY DERIVED, AND WHY NOT A NEW FRONT-MATTER ARRAY. main_ingredients is a deliberately partial HINT: fine to include ON, dangerous to exclude BY. Nine recipes list an olive oil in ingredient_groups and not one of them names it in main_ingredients, so "no olives please" answered from main_ingredients would hand back nine recipes containing the thing. Same shape for coriander (3 vs 8) and mushrooms (3 vs 4). A parallel hand-maintained array would duplicate a required field with nothing able to verify the copy, so this reads the real list. INCIDENTALS COUNT. `incidental: true` hides an item from main_ingredients and from the recipe page's own Ingredients section (see §4 of the handover), and that is right for "what is this dish made of" -- but "we didn't itemise the frying oil" is not an answer to someone avoiding it. No `unless item.incidental` here, deliberately. THE NAME IS TAKEN UP TO THE FIRST COMMA OR OPEN BRACKET, so "butter beans, drained" indexes as "butter beans" and matches the "butter beans" in another recipe that happens to carry no preparation note. Lowercased, and deduplicated within the row. SEPARATED BY `|`, NOT BY COMMAS, unlike data-ingredients above. That attribute joins main_ingredients, a curated vocabulary the taxonomy tests already keep comma-free; these are arbitrary `item:` free text, where the comma is the single commonest character (1,393 of the 3,751 item strings across recipes and drafts contain one) and is kept out of the value only by the truncation two lines up -- a separator whose safety depends on another rule in the same expression staying exactly as it is. `|` appears in no item string anywhere in either collection, and is already this file's chosen "cannot appear in the values" separator just below, in the pantry ordering.
