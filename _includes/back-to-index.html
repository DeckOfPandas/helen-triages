WHY history.back() RATHER THAN REBUILDING THE INDEX FROM A URL. Helen asked whether this could avoid a refresh "so the index page has the same recipe list I left it with", and the deciding fact is the shuffle: with no filters set the index reshuffles on every fresh load (MANUAL 13.7). So a link that rebuilds the index from a query string -- even a perfect one carrying every filter -- hands back a correctly filtered list in a DIFFERENT ORDER, which is not the list she left. Going back through history restores the page from the browser's cache instead: filters, page number, shuffle order and scroll position all intact, because the page was never re-rendered. The row is page furniture, not chrome: it lives in the page layouts rather than in default.html, because it is about where THIS page sits, not about the site shell. Helen: "back arrow and site door in navbar should use the same graphic", and asked for the navbar's: the site door (default.html's `.site-nav-icon-link`) is the word plus icons/arrow-right.svg, and this is that same file, mirrored. THIS IS #993'S FIX ARRIVING AT ITS SECOND SITE, and the reason is already written out in full beside the navbar's own include.
