Keys, each earning its place from the real data: amount the quantity AS WRITTEN ("0.5 oz", "3 dashes") — the display string, which carries units a number cannot ml the same quantity in millilitres, for ratios and scaling. ABSENT on purpose where the unit is not volumetric — a dash is not 0.8 ml in any way worth writing down. Duplicated on purpose and guarded by a test, the same idiom internal_temperatures.yml uses for its display/numeric pairs. item what the source calls it, brand-led when the source names a bottle ("Appleton Estate Reserve") generic what you would ever FILTER by ("Jamaican, moderately aged"). STRING OR LIST — a list means "either would do", never "and". character a property of THIS RECIPE'S use of the bottle, not of the bottle in the abstract (#441) — e.g. blackstrap. LIST. suggestion the bottle NAME(S) ONLY, never reasoning (#457). STRING OR LIST. note the reasoning that used to get smuggled into `suggestion` (#457) — its own line, always visible, no interaction. HEADLINE, CLASS LINE, CHARACTER, NOTE — settled 2026-08-24 after a design pass on #465/#460. The headline is `suggestion` when present (you shop by bottle name), falling back to `item`. The class line is `generic`; `character` folds onto it as a labelled parenthetical, never a sibling fact, because "moderately aged rum (blackstrap)" reads as if blackstrap were a TYPE of moderately-aged rum — real, live confusion with actual black rum — so it says "(character: blackstrap)" instead. `generic`/`suggestion` CAN BE A STRING OR A LIST, and Liquid's `for` quietly treats a bare string as a one-item sequence (verified against the real `liquid` gem, not assumed), so the same oxford-join loop handles both shapes with no type check anywhere. A rum-family style name (looked up via `ingredients.family_of`) gets a blockier monospace treatment with a quiet italic "or" between options — the internal commas in names like "Demerara, aged" collide with a plain list-join comma otherwise, and this is only true for rum (a name like "cognac" has no such collision, so it stays plain). NOT SOLVED HERE, deliberately: no spirit-word ("rum", "gin") is appended after a bare style name, because several families already bake their spirit into the string ("blanco tequila") and others don't ("bourbon" needs no suffix, "London dry" does) — auditing all of that is real, separate work, not a template one-liner. {% endcomment %} {% assign family_of = site.data.cocktails.ingredients.family_of %} {% if page.ingredients.size > 0 %}
