WHAT MARKS IT OUT IS WHAT IS ABSENT, which is the whole point: no method, no metadata grid, no source line. `.recipe--magic-bag` exists for the one spacing consequence of that (the badges have no metadata grid above them to sit under -- see _sass/food/_recipe-header.scss) and for nothing else. {% comment %} NO STANDING CAVEAT ON THE PAGE, AND THAT WAS A DECISION. Removed 2026-08-26, the day it was built, at Helen's ask on seeing it: "Delete the note at the top about the magic bag -- I am the user, and I know exactly what is going on." Worth recording because the reasoning for adding it was not wrong, it was aimed at the wrong reader. Her original ask was to promise future Helen that these lists are incomplete, and a caveat rendered on every page is a good way to make a promise you cannot forget to type. But it explains the collection to somebody who does not know what it is, and on this site that person does not exist -- the README is explicit that it is not written for anyone else. She knows a magic-bag page has no method because she knows what the magic bag is; the collection's name is already carrying it. THE PROMISE ITSELF IS NOT GONE, it just is not written on the page. It is in the schema: there is nowhere to put a method, and tests/test_magic_bag.py actively rejects one. A list that CANNOT be completed here is a stronger statement than a paragraph saying it might not be. So do not reinstate this on the reasoning that the pages "should explain themselves". If an entry ever genuinely IS complete and wants to say so, that is an opt-in `ingredients_complete: true` -- a fact about one dish, not a standing note about the collection. {% endcomment %} {% comment %} `.size > 0` rather than a bare truthiness test, for the reason _layouts/recipe.html gives at its own Ingredients heading: an empty array is truthy in Liquid, so `ingredients: []` would render the heading with nothing under it. tests/test_magic_bag.py requires a non-empty list, so this is the latent-twin guard rather than a live case. {% endcomment %} {% if page.ingredients.size > 0 %}
